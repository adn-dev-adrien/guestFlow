- **Website payment retries are no longer refused** (specs/public-online-payment.md rule 7, website-booking 1.5.1): `POST /public/v1/booking-requests/:id/pay` has its own `paymentStartLimiter` (default 20 / hour / visitor, `PAYMENT_START_RATELIMIT_MAX` / `_WINDOW_MS`) instead of sharing the 5 / hour booking-request budget, so a guest who sends a request then retries the payment a few times no longer gets a 429. SDK 1.7.0 exposes the new limiter.
- **WordPress plugin 1.16.1** (specs/wordpress-plugin-self-update.md rule 6, specs/wordpress-plugin.md rule 14): the self-update only accepts a `guestflow-booking-X.Y.Z.zip` asset of a GuestFlow release on github.com (repository and path checked, not just the host); a fully trusted `X-Forwarded-For` chain relays the connecting address instead of its client-written left-most hop; the payment redirect only follows an `https:` URL. `INSTALL.md` no longer suggests `curl -k`.
- Public documentation: private infrastructure details (LAN addresses, SSH login, container name, backup paths, a listing id, a personal mailbox) and real-looking guest emails in mock-ups are replaced by placeholders.
