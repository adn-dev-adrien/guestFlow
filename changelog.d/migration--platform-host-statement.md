- **Migration — platform brut re-based on the host amount** (spec `platform-host-statement-and-commission-vat.md` rule 4). Once, at the first start (`migrations`: `platform_host_statement_brut_v1`), the stored « brut » of every platform stay loses the tourist tax it held: mode « plateforme » with a filled box → `brut − box`; mode « nous reverse » → `brut − T` and the box takes `T`, the tax the engine subtracted on that row. Every stored price, schedule, tourist tax and accounting entry stays to the cent (a test re-prices one prod-shaped fixture per mode before/after); fees inside a historical brut stay. New columns: `reservations.platformOptionsAmount` (NULL on every existing row: no check on history) and `platforms.commissionVatRegime` (`hasVatOnCommission = 1` → `fr_vat`, else `no_vat`: exports stay byte-identical until the regimes are set, but for the new last CSV column).
- **Migration safeguards.** A stay whose tourist tax is frozen at 0 (priced while its platform kept the tax) is left exactly as it was, its tax box included; the stored sale figures of the stays the migration rewrites are written again; if the migration fails the server refuses to start rather than run the new semantics on old data.
