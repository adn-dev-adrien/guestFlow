- **Plugin dependencies, seen on both sides** (spec `plugin-dependencies.md`, 2026-10-29). One server-computed graph (`utils/pluginGraph.js`) over the manifests' `requires`, read by the Plugins page, the reconciler, the loader and the console. Every plugin view carries `dependencies` (« Nécessite … » with the status of an unmet requirement, « Utilisé par … ») and `actions` (activate / deactivate / uninstall, each with the plugins it takes along or the reason it is refused, said before the click). Install and activate take the requirements that are off along under one confirmation (`withRequirements`), deactivate takes the active dependants along (`withDependents`), all or nothing; uninstall never cascades. A development tree now installs from the same plan (a requirement was silently skipped there). A dependency cycle is refused `REQUIREMENT_CYCLE` and its members are left unloaded. `check-plugin-versions.mjs` fails a `requires` naming a plugin that is not shipped, a range the shipped version breaks, a self-requirement or a cycle. Console: « Nécessite / Utilisé par » under each module, switches that take the linked modules along with a confirmation, and a plan or option that allows a plugin without its requirement is refused.
