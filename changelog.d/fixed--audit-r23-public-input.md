- **A form refused for its input no longer locks the visitor out** (decision D18; `public-api.md` rule 9, `public-request-abuse-and-grouping.md` rule 6): a `422` on `POST /public/v1/booking-requests` gives its hit back to the 5-per-hour budget. Any other answer still spends it; the broad limit and the proof of work stand.
- **Public refusals follow the visitor's language** (`site-english-version.md` rule 8): the `429` of the public limiters, the `404` of an unknown `/public/v1` path and the API key's `401` / `403`. Code and status do not move.
- **One address reads as one address** (`clients.md` rule 12, `public-api.md` rule 21): an address holding a non-ASCII character is stored in lower case, so rules 7 and 12 of the public request see it, and format characters leave a public `guest.email` instead of making a second client that reads the same.
- **Public names and free text hold nothing invisible** (`public-api.md` rule 20, `public-request-abuse-and-grouping.md` rule 22, `site-traffic-analytics.md` rule 15): a name of Hangul fillers alone is `required`; control and bidi characters leave the message and the attribution before the length check and the fingerprint.
