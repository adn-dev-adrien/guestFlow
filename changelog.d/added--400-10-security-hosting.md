- **Accounts**: « Mot de passe oublié ? » sends a one-hour, single-use link (3 per address and 20 per IP per hour); two-step login (authenticator app or e-mail code, backup codes, trusted devices) locks for 15 minutes after 5 wrong codes — a two-step activation begun before the update must be restarted (« Recommencer »); support access is granted by the operator, with a journal. Writes under `/api` from another site are refused (403), and a hosted instance refuses its own update (403).
- **Hosting (control plane)**: a console deployed separately provisions and updates a fleet of instances, bills subscriptions in Qonto and sets the modules of each customer. An instance hosted on the platform reads a signed licence: it has no Plugins page (the console sets its modules), units and accounts beyond the plan are refused, and an unpaid subscription turns the instance read-only (reads, exports, calendar sync and payment collection keep working; the website stops taking new bookings). Inert for self-hosted installs. **Before upgrading the console, set `CP_SESSION_SECRET` and `CP_PROXY_SECRET`**: it refuses to start outside development and test without them.
