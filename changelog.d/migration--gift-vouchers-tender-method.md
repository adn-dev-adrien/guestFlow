- **Migration — `payment_tenders` accepts the prepaid method.** The CHECK on `payment_tenders.method` is widened to `'prepaid'` and the table gains the nullable columns `source`, `ref` and `label` (a plugin's prepaid line). SQLite cannot widen a CHECK in place: at the first boot the table is rebuilt in one transaction, every row, id and value copied as stored (existing split payments read exactly as before), its index created again; a second boot changes nothing. A rollback to the previous release runs on the rebuilt table (it knows neither the method nor the columns, and no row uses them until a voucher is applied).
