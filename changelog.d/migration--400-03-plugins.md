- New `plugins` table: `plugins_builtin_seed_v1` installs the twelve built-in plugins **active** on every existing database (one with a property or a reservation), so nothing changes on screen; a brand-new database starts with none. The registry adds `manifest`, `pinned_sha256`, `previous_version`, `previous_source`, `previous_sha256`, `rollback_until`, `off_at`; `builtin` rows become `bundled`. A database upgraded from master v3.10.0 or later keeps the state of its intake plugins.
- New `plugin_settings` table: `plugin_settings_from_app_settings_v1` copies the Météo-France key and the eight Google Agenda fields, and the Linge (8), Export comptable (4), Site WordPress (2), Paiement en ligne (19 `qonto*` columns, secrets as encrypted values) and Neat (13 `neat*` columns) settings. The old `app_settings` columns stay in place, unread, for one release (« Effacer aussi ses données » empties them).
- Plugin tables are created by their plugin on install (`neat_subscriptions`, `neat_price_cache`, the three laundry tables, `resource_bookings`, `guest_app_*`, `guest_sessions`, `guest_stay_links`, `guest_booklet_*`, `guest_media`, `guest_orders`, the website-booking `public_request_*` tables); an existing database keeps every row, and nothing is created for a plugin that is not installed.
- `hourly-resources`: `resource_bookings_v2` (offered time, payment lines and date, arrival, billing address and Qonto invoice columns; a booking already ticked « Payé » keeps it with no method and stays out of the accounting export; the Qonto connection must be reconnected once to grant the invoicing scopes), `_v3` (`paidVatRate`, `invoiceMarkPending`; paid bookings get the rate in force at install), `_v4` (`qontoClientIdentity`), `tag_evening_supplements_v1`, and `property_resource_prices.price` accepts NULL (`resource_property_price_nullable_v1`, table rebuilt with every value kept).
- `linen` 1.2.0: `laundry_schedule_versions` seeded once from `laundryWeekday` (every regular trip, pick-up and card of an existing install unchanged; a past manual line now stays counted for the week after it); `laundry_trip_manual_additions.bathMats` (0).
- `airbnb_intakes` and `gdf_intakes` gain `senderVerified` (rows already applied set to 1, open rows stay 0 and are proposed with the warning at the next pass).
- Plugin SDK 2.0.0 removes the client step contract `sas.arrival.steps[].recapLines`: a plugin built against SDK 1 and installed from outside this repository is refused until republished against `^2.0.0` (none known).
- `productisation_v1`, once, on a database that already holds properties or reservations: today's wording of the guest emails becomes data (stay texts, option phrases, confirmation order, nordic-bath sentence), Lodgify is marked as a direct sale, the push subject and the SAS extinguisher check are kept; new columns `platforms.countsAsDirect` and others; Solio's emails render byte for byte as before.
