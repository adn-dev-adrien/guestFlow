- **Plugin settings table** (spec `plugins-phase-1-sdk.md` §5): new table `plugin_settings (plugin_id, key, value, updated_at)`. The one-shot migration `plugin_settings_from_app_settings_v1` copies the Météo-France key and the eight Google Agenda fields there, byte for byte (secrets stay encrypted with the same key). The old `app_settings` columns stay in place, unread, so a rollback to v3.5 finds its data; they are dropped in a later release. Google stays connected and the weather key stays set.
- **Plugin tables created on install**: the tables of the five moved plugins (`weather_vigilance_cache`, `school_holidays`, `school_holidays_sync_state`, `tariff_recipe_runs`, `gate_key_results`, `gate_connector_state`) leave the core baseline. An existing database keeps them untouched (the plugins' migrations find them and only record themselves as `plugin:<id>:<name>` in the `migrations` ledger); a new database gets them when the plugin is installed. The 15 hard-coded school-holiday periods are no longer seeded: installing the plugin syncs from education.gouv. The Sowel connector keys are only created once `gate-access` is installed.
