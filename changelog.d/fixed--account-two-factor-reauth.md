- **Security: turning the validation in two steps off, new backup codes and a change of app now ask the password AND a current code, and the confirmation password is limited** (specs/hosting-h2-account-security.md rules 47, 49): until now the password asked in « Mon compte » had no attempt limit, so a stolen session could guess it through `/api/auth/2fa/start|disable|backup-codes`. Five wrong passwords within 15 minutes now lock the three routes for 15 minutes (429 `REAUTH_LOCKED`, written to the account history), and removing the protection or minting backup codes needs a current code (app, backup or emailed) on top of the password; a wrong code counts toward the existing 5-code lock. The password change (`POST /api/auth/change-password`) is behind the same limit, and a successful password reset by link clears it. A switch to the email code during a first activation needs the enrolment's random token (not just the session cookie) and is never accepted on a change of app. Code mails are limited atomically (60 s between two, 6 an hour, 5 per activation), the emailed re-authentication code no longer cancels a login code, and « Renvoyer le code » at login waits 60 s and has its own hourly budget.
