- **Wrong JSON types on the authenticated API** (audit R22; `hosting-h2-account-security.md` rule 68, `reservations-backend-mvc.md` rule 16, `plugins-phase-1-sdk.md` rule 7, `express-5-upgrade.md` rule 9). `{"toString":1}`, `true`, `{}` or `[1]` on a field used to answer 500 with a logged stack, or be stored as `[object Object]`: each now gets the field's refusal, with a last-resort `400 INVALID_FIELD_TYPE`. A password or code that is not a string is a wrong one and counts; a stay's times are `HH:MM`, its ids positive integers, its ticks true / false / 1 / 0, stored values sent back unchanged exempt; a planning card's `done: "false"` no longer ticks it; a plugin setting can no longer be overwritten by an object; a secret's field of spaces keeps it.
- **False crashes in the log** (audit R22, public findings 1-2). A compressed body that does not inflate, a dropped upload and a badly encoded path parameter are refused without an `[unhandled]` line.
- **Guest names** (audit R22, public finding 3). A first or last name with no letter or digit is refused as empty on the public form; control characters are never stored.
