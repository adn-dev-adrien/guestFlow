- **Website booking — stay rules** (audit 2026-10-27, `public-api.md` rule 12): the public booking request refuses a stay longer than the season's maximum (`409 MAX_NIGHTS`) or off its changeover days (`409 CHANGEOVER`), as the back-office does, with no override. `POST /quote` exposes `maxNights`, `maxNightsBreached`, `changeoverBreached` and `stayRefusal` (the sentence to print, FR/EN); the calendar's arrival windows only offer arrivals a stay can satisfy; `POST /booking-requests/:id/pay` re-checks the three rules on the saved devis. A night the engine reports as unpriced (`unpricedNights`) is unavailable on the site.
- **Website booking — availability re-check** (rule 15): `computeBlockedDates` reads reservations one day wider on each side, so a neighbour's late check-out or early check-in is seen by the exact-window checks of the quote, the request, the payment and the Google feed.
- **Website booking — options** (rule 14): the quote and the booking request accept only the options the public catalogue lists (no internal-only option, offered default or negative price); the admin API refuses a negative option price (« Le prix d’une option ne peut pas être négatif. »). The same option or resource twice in a request is a 422 instead of a 500 (rule 16).
- **Website booking — existing client** (rule 13): a request whose e-mail matches a client no longer changes that client's language; the typed identity, when it differs, is appended to the devis notes (« Client existant reconnu par l'e-mail — identité saisie : … »). Supersedes `site-english-version.md` rule 12.
