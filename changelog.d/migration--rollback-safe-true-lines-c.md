- **Update safety — going back to an older version after 4.2.0** (`specs/self-update-and-releases.md` rule 57). If the update to 4.2.0 fails its check and the application returns to 4.1.0 by itself, 4.1.0 finds a database it runs normally: the one change it cannot run on (the option and resource lines keyed by line) is applied only once 4.2.0 is confirmed. After that, installing an older version is refused, and a fiche saved by an older version cannot bill the departure charges a second time. Running an older version by hand on a database 4.2.0 has used is not supported.
