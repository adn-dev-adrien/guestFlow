- **A GuestFlow major no longer switches the plugins off** (decision D24, specs `plugins-phase-4-registry.md` rule 62, superseding rule 34, and `self-update-and-releases.md` rule 54; audits R34-CON-H1 = R34-P1). Every plugin declared « GuestFlow <4.0.0 », so installing 4.0.0 would have left all sixteen unloaded at boot (« Incompatible avec cette version. »), with no compatible version to offer: the site's booking engine, payment links, sas, accounting export and intakes off until a new release. A plugin is now judged on its SDK range and on the floor of its GuestFlow range; a package already installed with « <4.0.0 » keeps loading on 4.0.0 and later while SDK 2 is served. The sixteen manifests write a floor only (one patch bump each), the package build refuses a ceiling, and `check-plugin-versions` (every PR, the release `verify` job, the release skill's pre-flight with `--core-version X.Y.Z`) refuses a release whose own plugins its core or SDK would refuse.
