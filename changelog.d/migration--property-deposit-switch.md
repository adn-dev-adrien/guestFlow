- **`properties.publicDepositEnabled` → `properties.depositEnabled`** (spec `property-deposit-switch.md`, 2026-09-20). `ALTER TABLE … RENAME COLUMN` idempotent dans `database.js`, mirroré dans `schema.sql` ; toutes les valeurs stockées sont préservées. Le champ change de nom dans `/api/properties` (client et serveur voyagent dans la même archive) ; `/public/v1` n'est pas touché.
- **Changement de comportement : le défaut devient « pas d'acompte ».** La colonne valait déjà 0 partout, mais elle ne gouvernait que le site ; elle gouverne maintenant tout l'acompte. Conséquence : une réservation portant un acompte **non encaissé** sur un logement désactivé verra cet acompte basculer dans le solde au prochain recalcul de sa fiche (une modification, par exemple). Aucune migration ne réécrit les montants déjà annoncés à un client.
