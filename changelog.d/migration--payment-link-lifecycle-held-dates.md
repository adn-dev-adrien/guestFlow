- **Links already on taken dates are withdrawn once, without telling the guest** (`dates_taken_links_withdrawn_v1`, spec `payment-link-lifecycle.md` rule 61). At the first boot, every open payment link of an unpaid devis or reservation whose nights a stay holding its dates already covers is withdrawn (`cancelReason = 'dates-taken'`, the deactivation marker when it has a provider id), one `[migration:dates-taken-links]` line per link and a total; no network call at boot, the first poll pass reads each payment then deactivates the link (booked in date conflict if it was paid meanwhile). New table `dates_taken_notices` (one row per stay); each stay concerned gets a row `not-sent` / `upgrade`, which the coming « Dates prises » dashboard card shows as « client non prévenu » and which never triggers a guest e-mail. Nothing is deleted; paid rows are untouched.
