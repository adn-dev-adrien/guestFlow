- **A GuestFlow major does not switch plugins off by itself**: a plugin is judged on its SDK range and the floor of its GuestFlow range, so a package declared « <4.0.0 » keeps loading while SDK 2 is served. **A plugin whose required plugin is installed but off, or at the wrong version, is still switched off at boot** (e.g. Vigilance Météo-France over an off SAS plugin: the home reads « <Plugin> éteint : nécessite <Plugin> » with « À réactiver depuis la page Plugins », or « À mettre à jour puis réactiver depuis la page Plugins » when the version is wrong) — switch the requirement on or update it, then reactivate the dependant.
- **Plugins leave the core one after another**: Météo-France, school holidays, Google Agenda, tariff recipes, Linge, Export comptable, Site WordPress, Arrivée et départ guidés, Paiement en ligne, Neat and hourly resources are plugins with their own settings, tables and versions; nothing changes while they are installed. Uninstalled, a plugin leaves no trace and « Effacer aussi ses données » removes its data (prices, payments and the tariff journal are never touched); without a connected payment provider the fiche shows no payment-request button and the dashboard no « Relancer ».
- **Deactivating a plugin another active plugin requires is refused** (409 `REQUIRED_BY`). Plugin-created clients go through the client validation (`INVALID_CLIENT`, SDK 2.13.0).
- **Neutral seeds** for a new database only (no catering catalogue, no pool season, neutral guest emails; Lodgify counts as direct through « Compté comme vente directe »); Paramètres › Intégrations has one tab per plugin.
- **A hosted customer** no longer sees the plugin lifecycle (404 for every role); the operator sets the modules from the console. The start assistant asks 3 questions and a « non » switches nothing off.
