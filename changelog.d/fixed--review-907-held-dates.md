- **Held dates: the first boot after the install, failures while withdrawing, and a mint racing a booking** (spec `payment-link-lifecycle.md` rules 11, 12, 32, 48, 61, review of #907). The boot steps that withdraw payment links (links already on taken dates, a duplicate set aside) no longer load any model while the database module is being built, which left `/api/reservations` answering 500 on the first boot after the install until a restart. A failure while withdrawing a link never loses an iCal booking nor fails a save that succeeded: it is logged and the 15-minute pass withdraws the link (a disk-full or I/O error still fails the import as a whole, never half of it). A link whose nights were taken or closed while the payment provider was creating it is withdrawn and deactivated at once, and the request refused. The « Dates prises » badge no longer shows on a devis that is no longer open or on a stay already over, and gets a 44 px touch target on phones; the refusal dialog of a devis is titled « Devis non enregistré ». +10 server tests, +1 client test.
