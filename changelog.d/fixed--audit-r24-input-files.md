- **A WEBP or GIF logo no longer stops every devis PDF** (specs/settings.md rule 8, corrected): the logo upload takes a PNG or a JPEG only, judged on its name, its type and its first bytes, and the image must decode whole; a refused file leaves the stored logo as it was, and a new logo removes the former `company-logo.*` files of the other extensions. A logo already stored that the PDF cannot read (WEBP, GIF, damaged) gives the devis without its logo and a `[devisPdf] logo` line in the server log, instead of « Erreur lors de la génération du PDF. ».
- **A damaged property photo is refused by name** (specs/settings-input-guards.md rule 59): « Image illisible. » (400) on creation and update, nothing stored, instead of a 500 that dropped the rest of the form.
- **A long document name is stored, shortened, and an upload failure never shows the server's path** (specs/settings-input-guards.md rule 60): a name over about 240 characters used to answer `ENAMETOOLONG` with the absolute uploads path; any failure other than size or type now answers « Fichier non enregistré. ».
- **A template that names `{{constructor}}` or `{{toString}}` reads « Variable inconnue »** (specs/guest-email-texts-made-simple.md rule 11, reading of 2026-11-05), not the text of a native function.
- **The colour of an iCal source passes the platform colour check** (specs/platforms-and-ical-rework.md rule 17): a sent `platformColor` that is not a readable `#rrggbb` is refused with 400 `INVALID_FIELD`; a stored colour sent back passes. Any text used to reach the calendar chips as CSS.
- **A resource booking ends after it starts** (specs/resource-supplements-total-server-side.md rule 23, reading of 2026-11-05; `hourly-resources` 1.3.7): an end at or before the start is refused on the preview, the create and the update, unless both times are the stored ones; with a minimum duration of 0 it used to be stored at 0 €.
