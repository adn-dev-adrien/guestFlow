- **A payment mark stores the day it validated, and a payment flag must be a real true / false** (specs/reservation-payment-ledger.md rule 66, audit R20-M1): `PATCH /api/reservations/:id/payment` judged the first ten characters of a paid date but wrote the raw value, so a hand-made request could store `2026-11-01<b>x</b>` as a paid date (exported as is), re-date a note settled in the stay with an array (the note then fell out of the accounting journal), write a return date beside an unticked caution return, or record `depositPaid: "false"` as a received acompte. A non-string date is now refused (« Date invalide. »), the stored date is the judged `YYYY-MM-DD` (or the row's own value when it is sent back unchanged), a date sent with an unticked mark is never written, and every payment flag (and the « caisse interne » of a note) accepts only `true`, `false`, `1` or `0` — anything else is a 400 `INVALID_PAYMENT_FLAG` with nothing written. The fiche, the dashboard, the finance page and the bank reconciliation already send these shapes: nothing they do changes.
