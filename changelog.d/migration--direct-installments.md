- **Installment plans — schema** (spec `direct-installments.md` §5). New table `reservation_installments`; three additive aggregates on `reservations` (`installmentsPaidAmount`, `installmentsUnpaidAmount`, `installmentsTarget`, 0 for every existing row); `email_log.occurrenceKey` (`''` for every existing row). Two tables are rebuilt on boot, inside one transaction, rows copied one-to-one and ids kept: `payment_links` (its `type` CHECK accepts `installment`, new nullable `installmentId`) and `email_manual_queue` (primary key `(templateId, reservationId, occurrenceKey)`). Idempotent; no existing reservation has a plan, so no existing amount or date changes. The seed adds the manual template `installment_request`.
