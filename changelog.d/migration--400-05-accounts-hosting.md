- Account security: tables `password_reset_tokens`, `user_two_factor`, `user_backup_codes`, `user_security_events`, `support_access`, `support_access_links`, `support_access_log`; `users.twoFactorSnoozedUntil`; additive columns on `user_two_factor` (an activation begun before the update reads as expired: one click on « Recommencer »; protected accounts keep method, secret, backup codes and trusted devices).
- `users.isSupportAccount` marks the inactive « Support GuestFlow » account (`support@guestflow.invalid`, never listed, never counted); a trigger now refuses any write that reactivates, re-keys or unflags it, so a release below 4.0.0 cannot open it after a rollback.
- Control-plane database (separate from the instance database, a service 3.21.0 did not ship): it creates its whole schema on first start (`instances`, `fleet_updates`, `fleet_update_items`, `backup_checks`, `mail_counters`, `host_redirects`, `host_alerts` among others); a control plane from an earlier pre-release build gets `provisioning_steps` rebuilt once to accept `running` (rows kept). The instance database is unchanged.
- Every boot deletes the push subscriptions of an owner who is not an active, non-support administrator, so a row left by an older version cannot come back to life when an account is reactivated (devices of reception and accountant accounts included).
