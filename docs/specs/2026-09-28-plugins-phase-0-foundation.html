Plugins — phase 0 : la page Plugins, et ce qui n'est pas installé disparaît

Spec validée le 28 septembre 2026 · référence : specs/plugins-phase-0-foundation.md · découle de ton arbitrage D6 (12 plugins)

Le constat

Aujourd'hui, tout GuestFlow s'affiche pour tout le monde. Rien dans le code ne sait ce qu'est un plugin : pas de table, pas d'interrupteur, et le menu ne se filtre que par rôle. Un gîte sans bain nordique, sans Qonto et sans sas voit quand même leurs menus, leurs alertes et leurs boutons.

Ce qu'on propose

Pour toi et tes clients

  • Une page Paramètres › Plugins, comme sur Sowel : onglets Installés et Disponibles, recherche, Activer / Désactiver, Désinstaller en deux clics.
  • Un plugin inactif ne laisse aucune trace : menu, réglages, alertes du tableau de bord, boutons de la fiche, étapes du sas, cartes du planning.
  • Côté serveur, ses routes répondent 404 et ses tâches de fond s'arrêtent : désactiver Google Agenda arrête vraiment la synchro.
  • Solio ne voit aucune différence après la mise à jour : sur une base existante, les 12 plugins sont installés et actifs. Un nouveau client démarre sans aucun.

Les garde-fous

  • L'argent ne bouge jamais. Les séances de bain déjà vendues, la prime Neat déjà sur un séjour restent affichées et comptées ; seuls les outils pour en créer disparaissent.
  • Désactiver garde tout (ta réponse à Q1). En phase 0, désinstaller garde aussi les données : le choix d'effacer arrive en phase 1, quand chaque plugin aura ses propres tables.
  • Refus quand désactiver laisserait quelque chose en l'air : un lien Qonto encore en attente, un compte Accueil sans le sas, un compte Comptable sans l'export comptable.

À gauche, la future page Plugins. À droite, ce que voit l'utilisateur. Choisis une base de départ, puis active, désactive, désinstalle. Coche une situation en cours pour voir le refus.

Ce qu'on ne fait pas dans cette phase

  • Déplacer le code des plugins dans des paquets séparés, le SDK, les emplacements dans les pages : phase 1.
  • Effacer les données à la désinstallation : phase 1.
  • Télécharger des plugins depuis un registre : phase 4. En phase 0, les 12 sont livrés avec GuestFlow.
  • Retirer les contenus propres à Solio : chantier de productisation.

Les risques

  • Oublier une surface. Une trentaine d'endroits dans une douzaine de fichiers. Parade : la suite E2E tourne deux fois, tout actif puis rien d'actif, et échoue si une page appelle une route d'un plugin inactif.
  • Casser Solio. Parade : la migration active les 12 sur toute base qui a déjà un logement ou une réservation ; je vérifie sur une copie de la prod.
  • Le webhook Qonto répondrait 404 si on désactivait avec un paiement en cours : c'est pour ça que ce cas est refusé.
