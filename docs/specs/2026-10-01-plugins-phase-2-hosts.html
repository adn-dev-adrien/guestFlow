Plugins — phase 2 : le planning et le sas deviennent des hôtes, et quatre plugins sortent du cœur

Spec à valider · référence : specs/plugins-phase-2-hosts.md · branche feature/plugins-phase-2 → inte/plugins · une seule PR (ton choix P5)

Le constat

Après la phase 1, sept plugins vivent encore dans le cœur, derrière les interrupteurs de la phase 0. Cette phase en sort quatre : Linge, Export comptable, Site WordPress et Arrivée et départ guidés (le sas). Les trois autres (bain à l'heure, Neat, Qonto) écrivent des lignes de prix et des paiements : ils attendent la phase 3.

Ce que la cartographie a mesuré

  • Linge : 3 tables, 8 réglages. Le planning charge et dessine les cartes blanchisserie lui-même.
  • Export comptable : aucune table, un journal recalculé à chaque lecture. Ses 6 routes sont mêlées à celles des indemnités, qui restent au cœur.
  • Site WordPress : toute l'API /public/v1, aucune table. La clé d'API est créée à chaque démarrage, même sans le plugin.
  • Sas : un dialogue de 2 000 lignes. Sa validation écrit l'argent du séjour (530 lignes dans le modèle des réservations).
Six chemins tournent encore plugin éteint. L'écran les cache, le serveur non :
  • l'alerte de manque de linge du tableau de bord ;
  • l'alerte « Demandes du site » ;
  • les prix « Facturables au SAS » ;
  • le bouton sas de la page « À venir » ;
  • les étapes linge et serviettes, côté données et côté validation du sas ;
  • la notification d'arrivée, qui pointe vers le sas.

Le planning et le sas deviennent des hôtes :

  • le planning reçoit des cartes et des boutons de plugins (planning.days, planning.actions) ;
  • le sas reçoit des étapes, au départ aussi (sas.departure.steps), placées où le plugin le dit (after).

Ce qu'on ne fait pas

  • Bain à l'heure, Neat, Qonto : phase 3.
  • Les étapes de sas qui encaissent, venant d'un plugin : ce contrat arrive en phase 3, avec les lignes de prix.
  • La checklist de départ configurable : elle n'existe pas encore.
  • Les options de linge restent au cœur, parce qu'elles se vendent.
  • Le téléchargement des plugins : phase 4.
Le risque. Le sas et l'export comptable touchent à l'argent. On ne déplace donc pas ce code : la validation du sas et les données du journal restent dans le cœur, avec leurs tests. Seuls changent qui appelle ce code et qui l'affiche.

Déjà réglé à part :
  • le bug des CGV d'une demande convertie : PR #648, sur master ;
  • la synchronisation de inte/plugins avec master v3.8.0 : PR #649, à merger avec « Create a merge commit ».

Essaie : chaque plugin éteint ne laisse aucune trace

Coche ou décoche les quatre plugins. À gauche, le menu et les écrans ; à droite, ce que répond le serveur. En ocre, les six fuites d'aujourd'hui, que la phase 2 ferme.

Ce que répond le serveur

Essaie : désinstaller avec ou sans effacement

Linge, Export comptable et Site WordPress proposent maintenant « Effacer aussi ses données ». Le Sas, non : tout ce qu'il enregistre fait partie des séjours. Clique sur un nom pour ouvrir son détail.

Essaie : la page « Indemnités d'annulation »

Elle reprend la section qui n'existait que sur Comptabilité. Elle est désormais au cœur, donc visible sans l'export comptable. Change de rôle, de mois et de largeur, ajoute une indemnité (essaie un montant vide ou négatif), encaisse-la, rouvre-la.
