Textes des emails : une page, un aperçu, un fichier

Spec specs/guest-email-texts-made-simple.md · 08/10/2026 · branche feature/email-texts-made-simple (depuis inte/plugins) · rendu avant l’implémentation, arbitrages 5–6 ajoutés pendant
En une phrase. Un nouveau propriétaire saisit quelques faits par logement et reçoit des mails complets ; une phrase se change sur une seule page, dans l’ordre où le voyageur reçoit les mails, avec le vrai mail à côté. Solio ne voit aucune différence.

Le constat

Écrire est encore difficile

  • Le texte se tape à cinq endroits : modèles, textes de séjour, textes par logement, accroche J-7 (cachée dans le modèle J-7), mentions.
  • Les boutons de variables sont une constante du client : ~30 variables, ~40 autres sans bouton.
  • Une variable inconnue est effacée en silence dans un modèle, mais refusée dans un texte de séjour.

Le mail d’un nouveau client est creux

  • Aucun aperçu pendant la saisie, aucun envoi de test.
  • Le J-2 neutre ne dit ni l’adresse, ni comment entrer, ni le Wi-Fi : aucun champ ne les porte.
  • Un téléphone vide donne « appelez-nous au . ».

Ce qu’on propose

A · Faits d’arrivée par logement

Adresse, lien carte, accès FR/EN, code de la boîte à clés, Wi-Fi. Code et mot de passe Wi-Fi chiffrés et masqués. Trois paragraphes composés par le serveur, absents si vides.

B · Ce qui manque est calculé

GET /api/email-readiness : nom, téléphone, expéditeur, article du logement, adresse et accès, EN manquant, variable inconnue. En tête de page, à la fin de l’assistant, et une alerte du tableau de bord à 14 jours.

C · Une page, dans l’ordre d’envoi

Confirmation → acompte/solde → J-7 → J-2 → lendemain → relances → annulation. Chaque section montre ses phrases, ses mentions, l’accroche et l’objet ; le modèle brut est derrière « Modifier le modèle complet ». Variables affichées par leur nom.

D · Aperçu en direct, test

Le serveur rend le brouillon (POST /api/emails/preview) sur le prochain séjour concerné, ou « Exemple ». FR/EN, repli signalé. « M’envoyer un test » : objet « [Test] », rien n’est historisé.

E · Un fichier

Un CSV ; UTF-8 avec BOM : objets, textes, mentions, accroches, accès. Réimport en une transaction, résumé avant d’enregistrer, ligne refusée avec son numéro. Cellule vide = garder, - = vider.

F–G · Anglais et démarrage

« Traduire les textes manquants » par la clé de la plateforme, variables protégées, marqué « à relire ». L’assistant gagne l’étape « Vos emails » avant « C’est prêt ».

Ce qu’on ne fait pas

  • Un éditeur riche (WYSIWYG).
  • Une bibliothèque de tons alternatifs.
  • L’import .docx : la mise en forme coupe les variables.
  • Des modèles par canal (Airbnb, Booking…).
Le risque. Un mail de Solio qui change. Trois parades :
  • le J-2 neutre n’est utilisé que par une base neuve ; les modèles enregistrés de Solio ne sont jamais réécrits ;
  • les propriétés de Solio n’ont aucun fait d’arrivée : les trois paragraphes sont vides, et les modèles de Solio ne les citent pas ;
  • le test productisation-golden reste inchangé, et chaque réservation de la copie de la base est rendue 6 mails × 2 langues avant/après : 0 différence exigée.
Second risque : les secrets. Code et mot de passe Wi-Fi sont chiffrés, jamais exportés, jamais journalisés.

    Arbitrages

    Tous tranchés avec l’option recommandée, sur instruction de dérouler le plan.

    1 · Import avec des lignes refusées

    Retenu : les lignes valides s’enregistrent à la confirmation, les refusées sont listées et ignorées.
    Écarté : tout bloquer tant qu’une ligne est refusée.

    2 · « Article jamais confirmé »

    Retenu : un logement enregistré par sa fiche a confirmé son article ; seuls ceux créés par l’assistant sans choix restent à confirmer. Les logements existants sont confirmés à la migration.
    Écarté : demander une confirmation à tous les logements.

    3 · Code portail et code de la boîte à clés

    Retenu : quand le séjour a un accès portail (plugin actif), le paragraphe d’accès omet le code de la boîte.
    Écarté : afficher les deux codes.

    4 · Nom de variable du paragraphe Wi-Fi

    Retenu : la variable de modèle s’appelle arrivalWifiParagraph : wifiParagraph existe déjà (« pas de wifi » du J-7) et doit garder son sens pour Solio. Les clés de texte restent celles de la spec.

    5 · Anglais vide

    Retenu : un modèle anglais vide ou un « accès » anglais vide envoie le français ; toute autre phrase sans anglais reste absente de l’email anglais, comme aujourd’hui, et l’aperçu le dit (« phrase absente de l’email anglais »). Le test golden de Solio contient une accroche sans anglais : la remplacer par le français changerait ses emails.
    Écarté : envoyer le français pour toute phrase sans anglais.

    6 · Article dans l’assistant

    Retenu : les cinq articles qu’un logement accepte (au, à la, à l’, aux, à), affichés avec le nom du logement ; pas de « dans le ».

    7 · Traduction

    Retenu : l’API Messages d’Anthropic (claude-sonnet-5-5), appelée sans SDK supplémentaire. Les variables sont remplacées par des marqueurs avant l’envoi et vérifiées au retour ; un marqueur perdu annule tout.
