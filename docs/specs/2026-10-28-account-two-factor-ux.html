Validation en deux étapes

« Mon compte » — l’activation du « Second code » refaite comme sur les autres sites : une fenêtre en 3 étapes, un QR code ou un bouton sur téléphone, un seul code, les codes de secours mis de côté avant de fermer. La sécurité ne baisse nulle part et une faille se ferme. Spec amendée : specs/hosting-h2-account-security.md, règles 38 à 53.

Le constat

C’est bien la double authentification

Le « Second code » est déjà la fonction habituelle : appli d’authentification (TOTP, comme Google Authenticator ou le trousseau de l’iPhone), code par email en secours, 10 codes de secours, appareil de confiance 30 jours, verrou après 5 codes faux, journal du compte. C’est la présentation qui n’est pas celle qu’on connaît.

Ce qui manque

  • Sur téléphone, rien n’est prévu : le téléphone qui porte l’appli ne peut pas scanner son propre écran. Pas de lien vers l’appli, la clé n’a pas de bouton copier.
  • Un code faux dit « Code incorrect. » sans le nombre d’essais ; au 5e, le formulaire disparaît sans explication.
  • « Terminé » ferme les codes de secours sans qu’ils aient été copiés ni téléchargés.
  • Une fois activée : une seule ligne, et pas moyen de changer de téléphone sans tout désactiver (le compte reste nu entre les deux).
  • Une activation commencée n’expire jamais.

Une faille trouvée en lisant le code

Le mot de passe redemandé pour activer, désactiver ou renouveler les codes n’a aucune limite d’essais (seule la limite générale de 3000 requêtes / 15 min s’applique, twoFactorController.js:49). Une session volée peut donc deviner le mot de passe par ces trois routes. Règle 49 : 5 essais faux en 15 min bloquent 15 min, avec une ligne au journal.

Ce qu’on propose — la maquette

Tout se manipule. Mot de passe de démo : maison (tout autre est refusé). Le bon code est dans l’« appli » simulée à droite ; un code faux montre le refus et les essais restants. Les trois réglages « Nom », « Confirmation » et « Email » sont les arbitrages en attente : les essayer ici.

Ce qu’on propose — les règles

L’activation

  • Désactivée : un statut, une phrase, « Activer ». Rien d’autre dans la carte (39).
  • 3 étapes dans une fenêtre, plein écran sur téléphone : mot de passe → appli → codes de secours. Annuler aux étapes 1–2 ne laisse rien derrière (40).
  • Ordinateur : QR code, clé à la main repliée. Téléphone : « Ouvrir dans l’appli » (lien otpauth://), « Copier la clé », QR replié. Choisi selon le type de pointeur, pas la taille d’écran (41).
  • L’entrée dans l’appli porte « GuestFlow » et « Entreprise · email » : reconnaissable dans une liste (41).
  • Un champ, envoyé au 6e chiffre comme à la connexion. Refus : essais restants, puis « Vérifier l’heure du téléphone. », au 5e « Recommencer » (42). Expire après 15 min (43).
  • Email en secours sous l’appli, renvoi après 60 s, 5 envois maximum (44).
  • Codes de secours : « Terminé » attend la case « Codes enregistrés en lieu sûr », cochée d’office par Copier ou Télécharger (45).

Une fois activée

  • Méthode et date, codes restants « 8 sur 10 » ; à 3 ou moins, la ligne passe en alerte avec « Nouveaux codes » (46).
  • Changer d’appli sans désactiver : l’ancienne appli marche jusqu’à ce qu’un code de la nouvelle soit validé ; appareils de confiance conservés (48).
  • Désactiver, nouveaux codes, changer d’appli : mot de passe + un code (selon Q2) (47).
  • Mot de passe de confirmation limité : 5 essais / 15 min (49). Journal plus parlant, replié sous « Historique » (46, 50).
  • La carte du tableau de bord ouvre directement la fenêtre (51).
  • Nom unique partout : carte, tableau de bord, Utilisateurs, journal ; la recherche des réglages trouve aussi « Second code » et « 2FA » (38).

Ce qu’on ne fait pas

  • Les clés d’accès (passkeys / WebAuthn) : la suite logique, une spec à part.
  • Rendre la validation obligatoire, ou afficher l’état de chaque utilisateur dans Paramètres › Utilisateurs.
  • Les SMS, plusieurs applis en même temps, l’impression des codes (Télécharger puis imprimer suffit).
  • Aucun changement de la connexion elle-même (écran « Vérification », appareil de confiance, verrou).

Le risque

Faible côté données

Trois colonnes ajoutées à user_two_factor, sans réécriture. Une activation commencée avant la mise à jour est vue comme expirée : un clic sur « Recommencer ». Les comptes déjà protégés ne voient que la nouvelle carte.

À vérifier sur un vrai iPhone

Le lien otpauth:// ouvre le trousseau d’iOS ou l’appli installée ; sans appli, le navigateur affiche son propre refus — d’où « Copier la clé » juste en dessous. Si Q2 = mot de passe + code, serveur et client partent dans la même version (le client actuel n’envoie pas de code). Taille : ~12 fichiers, 2 lots (serveur, puis client + E2E), ~48 tests nouveaux ou réécrits.
