Les modules se règlent dans la console, plus chez le client

Spec specs/plugin-operator-provisioning.md · brouillon du 28/10/2026 · amende les specs phase 4 (P25), plans et accès (règles 5, 11), phase P (règles 40, 43)

« Ce n'est pas l'utilisateur qui va activer les plugins, mais bien moi lorsque je vais configurer le guestflow pour un client. Il faut donc que l'installation des plugins soit gérée via une autre interface et que ça n'apparaisse pas chez un client guestflow. »

Le constat

Aujourd’hui, l’admin du client fait tout

  • Paramètres › Plugins : installer, activer, désactiver, effacer, mettre à jour, revenir en arrière.
  • Les routes /api/plugins/* ne demandent que le rôle admin : un admin client (ou une session support) peut tout appeler.
  • L’assistant de démarrage pose 3 questions qui installent des plugins.
  • Une page de plugin éteint affiche « Plugin inactif » et « Ouvrir Plugins ».
  • Les chips « Forfait Pro » et « Inclus dans le forfait…, sur demande » s’adressent au client.

C’était le choix P25 du 08/10 : « l’administrateur de l’instance installe ».

La console a déjà presque tout

  • Une licence signée déposée dans le dossier de l’espace, relue chaque minute : elle dit déjà quels plugins sont permis.
  • La console lit déjà la table plugins de chaque espace (colonne « Plugins » de la flotte).
  • Les mises à jour de plugins et du cœur passent déjà par « Versions » sur un espace hébergé.
  • Un journal d’audit existe.

Il manque seulement : qui décide de ce qui tourne, et l’effacement côté client.

Ce qu’on propose

Une section Modules sur la fiche client de la console. Un interrupteur par module. Le choix part dans la licence signée ; l’espace l’applique tout seul en moins d’une minute, sans redémarrage. La console relit le résultat. Rien n’entre dans l’espace : aucun port, aucun compte opérateur.

1 · ConsoleAdrien bascule « Linge ». Ligne d’audit, licence réémise.
2 · Licence signéeactivePlugins rejoint plugins. Inviolable sans la clé privée de la console.
3 · L’espace appliqueInstalle, active ou désactive par le code existant. Écrit le résultat ; la console le lit.

Maquette 1 — ce que voit l’opérateur

Essayer : éteindre « Réservation depuis le site » (refusé, Google Vacation Rentals en dépend) ; éteindre « Paiement en ligne » (bloqué, liens ouverts) ; allumer « Export comptable » (en attente puis actif) ; « Réessayer » sur l’échec ; effacer les données d’un module éteint (le slug doit être tapé) ; ouvrir « Hors forfait ».

      Ce qu’on ne fait pas
      
  
        
    
      • Pas de compte opérateur caché dans l’espace : il faudrait un mot de passe par client, une route que le client peut deviner, et son accord à chaque passage.
        • 
    
      • Pas de réglages de module dans la console : clés Météo, compte Qonto, stock de linge restent dans l’espace, chez le client ; Adrien les règle par l’accès support consenti.
        • 
    
      • Pas de changement pour Solio ni pour le dev ou l’E2E (espaces non hébergés) : la page Plugins y reste, leur propriétaire est l’opérateur.
        • 
    
      • Rien de nouveau pour les mises à jour : elles passent déjà par Versions › Plugins.
        • 
    
      • Pas d’activation en masse sur toute la flotte, pas de liste « Modules inclus » côté client, pas d’offre en libre-service.
        • 
  
      

  
      Le risque
      
  
      
    moyen
      Un module qui bascule sans qu’on le veuille. À la mise en service, la console relève d’abord ce que chaque espace fait tourner et n’envoie le choix qu’ensuite : la première application ne change rien. Un espace illisible ne reçoit aucun choix.
      
    moyen
      Un module éteint alors qu’il sert. Les garde-fous actuels tiennent : liens de paiement ouverts, comptes Accueil ou Comptable, module requis par un autre. La console affiche « Bloqué » et le module reste actif.
      
    faible
      Effacement par erreur. Seulement sur un module éteint, slug à taper, journalisé, et rattrapable par « Restaurer à une date ».
      
    faible
      Navigateur déjà ouvert. Un module éteint disparaît à la requête suivante ; un module allumé apparaît au prochain chargement de page.
      
    faible
      Taille : 4 lots, environ 30 fichiers, 13 fichiers de tests (≈ 88 cas). Lots 1 → 3 dans la même version.
