Plugins — phase 3c : ressources à l’heure

Spec specs/plugins-phase-3c-hourly-resources.md · brouillon du 05/10/2026 · branche feature/plugins-phase-3c · aucun code écrit
Deux défauts d’argent en production aujourd’hui. Après le sas, une soirée peut être facturée deux fois ; rouvrir le sas double le supplément. Démonstration ci-dessous, avant et après la correction.

Constat

Ce qui est dans le cœur et ne devrait pas

  • Réservations hors séjour, occupation, créneaux, cartes d’allumage et de séance.
  • La branche « séances » du moteur de prix.
  • L’étape « Créneaux » du sas, côté serveur.
  • Les variables d’e-mail du bain, trouvé par le mot « nordique ».
  • Côté client : Calendrier › Ressources, les champs horaires du formulaire, le sélecteur de séances, les cartes du planning.

Les 7 défauts relevés

  • 1. Soirée facturée deux fois après le sas.
  • 2. Supplément doublé à la réouverture du sas.
  • 3. Plugin éteint : le serveur planifie, tarifie et rappelle encore les séances.
  • 4. Toute ressource avec « heure offerte » ou « à créneaux » est tarifée à l’heure.
  • 5. Les recalculs perdent les séances.
  • 6. Les e-mails cherchent le bain par son nom.
  • 7. Aucun point d’extension pour tarifer une ligne, écrire au sas, placer une carte horaire ou ajouter un menu.

Ce qu’on propose

Trois contrats du cœur

  • Contributeur de ligne de prix : le plugin tarife la ligne dans la boucle du moteur ; le gel des lignes vendues reste au moteur et couvre désormais ces lignes.
  • Contrat de validation du sas : vérifier, ajouter des lignes de complément marquées, écrire dans la transaction.
  • Trois emplacements : resources.fields, reservation.resourceLine, calendar.menu ; planning.days accepte une heure.

Le plugin hourly-resources

  • Reprend tout le code horaire, aux mêmes URL.
  • resource_bookings devient sa table, toutes les lignes gardées.
  • Aucun contrat extérieur ne change : API publique, URL, noms des variables d’e-mail.
  • En production, rien de visible ne bouge, sauf les deux défauts corrigés.

3. Désinstaller avec effacement

Hors séjour

Désinstaller « Ressources à l’heure » ?

Ce qu’on ne fait pas

  • Les étapes linge du sas restent sur leur interrupteur de la phase 2 ; elles passeront au contrat de validation ensuite.
  • La colonne resources.showsPlanningCard garde son nom.
  • Le texte du rappel « maillot, serviette » reste au cœur (contenu Solio, sujet déjà ouvert).
  • Les réservations hors séjour restent hors compta, comme aujourd’hui.

Risques

  • Moteur de prix : la branche séances sort de pricing.js. Les suites de parité (pricing-*, sas-*, devis-extras-parity) doivent rester vertes, à l’euro près, pour Solio.
  • Lignes de supplément existantes : la migration les reconnaît par leur libellé « — supplément soirée ». Une ligne renommée à la main ne serait pas reconnue ; elle reste alors une ligne libre, à son montant.
  • Navigateur resté ouvert sur l’ancien sas : le serveur ignore un supplément renvoyé sous forme de ligne libre.

Arbitrages en attente

La spec suit l’option recommandée de chaque question ; rien n’est codé avant validation.
